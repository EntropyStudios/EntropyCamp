## Local Blender study

The first editable study is generated by `scripts/build_outer_wilds_blender.py`. It intentionally uses original procedural geometry and materials rather than pretending that reference images are 3D assets.

Local-only outputs are kept under the ignored `private/outer-wilds-blender/` directory:

- `outer_wilds_catalog.blend` and `outer_wilds_catalog.png`: twelve labeled groups for visual comparison.
- `outer_wilds_system.blend` and `outer_wilds_system.png`: an animated 240-frame system composition.

The current system scene contains 214 objects, 134 meshes, and 55 materials. It covers the Sun and Sun Station, Hourglass Twins and sand column, Timber Hearth and Attlerock, Brittle Hollow and Hollow's Lantern, Giant's Deep and the Orbital Probe Cannon, Dark Bramble, the Interloper, Quantum Moon, White Hole and station, the Stranger, the Eye, and the Deep Space Satellite.

No Windows partition is accessed by the extraction workflow. All official-asset study uses the explicit Linux-side copy documented below.

## Verified local game extraction

On 2026-09-18 a complete game copy was made available at `/mnt/mydisk/OuterWildsSource/`. Its manifest contains 168 asset bundles with no missing entries, including the base-game planets and the Echoes of the Eye `ringworld` and `dreamworld` groups.

The first verified extraction uses AssetStudioModCLI v0.19.0 in `SplitObjects` mode to export `TimberHearth_DistantProxy`. The result contains the official distant-view Timber Hearth and Attlerock meshes, hierarchy, five source materials, and the associated texture set. Blender 5.2.2 imports it as 8 extracted meshes; the prepared inspection scene contains 148,639 polygons after presentation geometry is added.

### Browser High-LOD Asset Set

The local-only web asset set is generated under `private/outer-wilds-extracted/web-high-assets/`. It contains 19 independent GLBs: the base-game celestial bodies and anomalies, the Stranger exterior, the ringed homeworld sky representation, the Eye distant proxy, the player ship, a Nomai shuttle, and the Vessel exterior. Dreamworld and ringworld interior terrain are intentionally excluded.

The profile caps geometry at approximately 56,000 triangles, caps texture edges at 1024 pixels, flattens object fragments to reduce draw calls, encodes textures as WebP quality 80, and enables `EXT_meshopt_compression`. The final validated set contains 599,536 triangles and occupies 21.38 MiB as GLBs. `manifest.json` records exact per-asset metrics and provenance.

Ash Twin needs a special reconstruction because its dynamic sand shell is a `TessellatedSphereRenderer`, not an ordinary mesh. The browser asset uses the extracted game sphere, sand tint, heightmap, and normal map in a glTF-compatible PBR reconstruction. The oversized Eye symbol effect is excluded from the Eye proxy so it cannot distort the body bounds.

Rebuild commands:

```bash
private/outer-wilds-tools/venv/bin/python scripts/extract_outer_wilds_special_assets.py \
  --data /mnt/mydisk/OuterWildsSource/Outer.Wilds.v1.1.16-P2P/OuterWilds_Data
blender --background private/outer-wilds-extracted/scale-catalog/outer_wilds_true_scale_catalog.blend \
  --python-exit-code 1 --python scripts/prepare_outer_wilds_web_high_assets.py
```

The black/white-hole study has been absorbed into `graph-3d.js`. The production graph renders the scene to an offscreen target and applies the pointer black hole, white hole and solar occlusion in one screen-space lensing pass. The compact distortion approach was inspired by Otto Seiskari's MIT-licensed WebGL implementation; the retained license is in `docs/licenses/oseiskar-black-hole-MIT.txt`.

### Sun And DLC Inspection Scene

`private/outer-wilds-extracted/sun-and-dlc/blender/outer_wilds_sun_dlc.blend` contains six independent groups with a catalog camera and six detail cameras. It opens in Material Preview. The original nine-body catalog remains unchanged.

| Group | Extracted Render Meshes | Scope |
| --- | --- | --- |
| `stranger_exterior` | 106 | Detailed exterior shell and separate static solar-sail frame, assembled from original scene transforms |
| `stranger_interior` | 394 | Streamed terrain, intact dam, artificial sun and selected landmark proxies |
| `dreamworld` | 122 | Four upper terrain regions and selected landmark proxies, retaining their original spatial arrangement |
| `visible_homeworld` | 2 | Ringed planet visible in the dreamworld sky |
| `sun_station` | 2 | Official distant proxy |
| `sun` | 1 | Game sphere mesh with a Blender reconstruction using extracted Sun heightmap, color-ramp and tint/motion inputs |

The final saved scene has approximately 2.30 million triangles and 57 packed image resources. Extraction completed with zero missing mesh/texture errors for the selected groups. Sources are recorded in `private/outer-wilds-extracted/sun-and-dlc/scene-data/manifest.json`.

This is a static asset-inspection scene, not a full playable DLC reconstruction. Instanced vegetation, all props/characters, simulation effects, dynamic fluids, cloak rendering and the complete Unity shaders are not restored. Screen, water and stencil occluders are retained but hidden for inspection. Their hidden-state reasons are recorded on the objects. Broken dam states are not overlaid on the intact model.

The Sun's runtime surface is produced by `TessellatedSphereRenderer`. The exported `SunProxy` is shader-deformed geometry, not an immediately renderable sphere, and is retained in a separate hidden Collection. The visible sphere is an extracted game geodesic mesh used as a substitute for runtime tessellation; its material uses the original Sun textures but is an explicitly labeled Blender approximation, not a claim of exact Unity fidelity.

The scripts use `UnityPy==1.25.3` and `TypeTreeGeneratorAPI==0.0.10`. Assembly metadata is read to decode `StreamingRenderMeshHandle`, `StreamingMaterialTable` and `StreamingTextureLookup`; game assemblies are not executed. Mesh arrays preserve UVs, custom normals, vertex colors, triangle indices and submesh/material assignments. DXT5nm normal maps are decoded from alpha/green into Blender RGB normals while retaining the original images.

Rebuild the selected assets from the Linux-side copy:

```bash

  --data /mnt/mydisk/OuterWildsSource/Outer.Wilds.v1.1.16-P2P/OuterWilds_Data
```

## Decision

There is no complete, browser-ready, clearly licensed 3D pack of the Outer Wilds planets that can be safely dropped into this repository.

The closest existing resources are:

1. A very complete live-wallpaper recreation containing cut-out PNGs for almost every body and a 22-minute timeline. It is 2D and the repository has no license, so it is reference-only.
2. Outer Scout, an MIT-licensed Blender tool that can reconstruct planet scenes from a legally owned local game installation. The tool is reusable; the extracted meshes and textures remain game assets and must not be committed or redistributed.
3. A small set of downloadable Sketchfab fan models. These cover props and characters, not the planets as a set, and several are far too dense for a browser graph.
4. Official screenshots, development articles, artist portfolios, and the Unity art talk. These are the best shape/material references, but not reusable asset files.

The recommended production path is therefore:

- Build the celestial bodies ourselves from low-poly geometry, procedural textures, and small custom shaders.
- Use Blender only for the few silhouettes that are awkward to construct in Three.js.
- Use official material only as visual reference. Do not copy extracted textures into the repository.
- Keep the Outer Wilds layer clearly unofficial, free, and optional, with the Mobius fan-content disclaimer and a credits page.

This also fits the current UI better: most graph bodies are only tens of pixels wide. Exact game terrain would cost much more GPU memory while looking worse at that size.

## How each planet should actually be made

### Shared body system

Use a common `createBody(archetype, seed, quality)` factory rather than a separate renderer for every planet. Each result should expose `object3D`, `update(elapsed, state)`, and `dispose()`.

- Base geometry: `IcosahedronGeometry` with deterministic vertex displacement. This reads more like Outer Wilds than a perfectly smooth UV sphere.
- Color: broad gradients and large graphic regions. Mobius describes the shipped look as sharp stylized geometry plus simplified textures and large-scale gradients.
- Detail: geometry or masks for the silhouette-defining feature only. At graph scale, silhouette matters more than small surface detail.
- Lighting: one shared sunlight direction plus restrained emissive accents. Avoid a separate real light per body.
- Identity: choose an archetype deterministically from the thread ID so a conversation remains visually recognizable across reloads.
- State: status changes orbit, size, halo, and animation rate; it should not randomly replace one planet with another.

### Sun

Use one subdivided icosphere and a shader with two scrolling noise octaves. Displace vertices slightly, mix amber/yellow/white emission, and add a camera-facing corona sprite. The star can remain the model node in the existing graph. Do not add a point light for every model node; use emissive shading and at most one shared light.

### Hourglass Twins

Make both bodies one reusable group. The sand transfer is the identifying feature and must be geometry/particles in 3D, not a painted texture. Represent the changing sand level with a latitude mask that moves in opposite directions on the two spheres. Towers only need readable silhouettes at the exposed pole.

### Timber Hearth and Attlerock

Use crater depressions in the base mesh, not normal-map-only craters. Add 20-40 instanced low-poly tree cones on Timber Hearth; scale instances by LOD. The atmosphere is a second back-sided Fresnel shell. Attlerock reuses the crater generator without atmosphere.

### Brittle Hollow and Hollow's Lantern

Brittle Hollow cannot be a textured sphere. Generate a shell, split it into a limited set of irregular indexed chunks, leave visible gaps, and place a small distortion disk/black sphere at the center. Chunks may wobble or occasionally detach, but the animation should be deterministic and reversible. Hollow's Lantern uses a black crust mesh above an emissive lava sphere plus a few pooled lava openings.

### Giant's Deep

The official breakdown describes an atmosphere shell, several overlapping cloud textures, rotating spiral polar caps, translucent heat lightning, wandering joint-based tornadoes, and ocean deformation. For the graph we only need the first four cues: ocean core, two counter-rotating translucent cloud shells, polar spirals, and brief lightning arcs. Floating islands can be 3-5 instanced rock/green clumps just below the atmosphere.

### Dark Bramble

Prioritize the silhouette. Build 5-8 jagged ice-shell pieces around a dim fog core and connect them with 4-7 thick branching curves. Mobius built the real vines as reusable interlocking tube segments with projected sculpt detail; our small version can use tapered `TubeGeometry` with low radial segments and sparse spikes.

### Interloper

Use a lopsided elongated nucleus with two material regions: blue-white ice and a dark fissure. The tail is a camera-facing ribbon or a small point trail whose length follows orbital velocity. It is also the natural visual language for inactive, low-priority conversations.

### Quantum Moon

Keep one mesh and six material presets derived from the nearby world palettes. Move it only during a dithered fade, never as a visible linear flight. Reduced-motion mode should cross-fade without relocation animation.

### The Stranger

This is the one body that benefits most from Blender. Model it as a low-segment rotating ring, a dark exterior cloak, a bright inner landscape band, a central artificial sun, and simple sail panels. A 2-5k triangle GLB is sufficient for the graph. Full interior architecture is unnecessary.

## Asset and performance budget

The graph recently had a WebGL context/memory problem, so the theme must have explicit limits.

| Resource | Target | Hard ceiling |
| --- | --- | --- |
| Visible planet triangles | 1,000-4,000 each | 8,000 each |
| Total graph triangles | under 80,000 | 150,000 |
| Texture size | procedural or 256-512 px | 1024 px for a hero body |
| Texture memory | one shared atlas where possible | 32 MB total |
| Draw calls | instancing/shared materials | under 80 |
| Lights | ambient + one directional | 2 real-time lights |
| Renderer | reuse the current single renderer | never create per-body contexts |
| LOD | far icon / near selected | 2 levels minimum for Blender assets |

The current project has Blender 5.2.2 LTS installed. The local Three.js runtime now includes `GLTFLoader`, Meshopt decoding and Trackball controls. Extracted game GLBs remain under ignored `private/` storage and are exposed only through explicit localhost allowlists.

## Proposed implementation order

1. Build the shared low-poly body factory and three unmistakable prototypes: Timber Hearth, Giant's Deep, and Brittle Hollow.
2. Validate them in the real graph with many nodes at desktop and mobile sizes, including selected-node cards and reduced motion.
3. Add Twins, Dark Bramble, Interloper, Attlerock, Hollow's Lantern, and Quantum Moon.
4. Add the optional 22-minute ambient timeline only after ordinary status updates remain readable.
5. Build The Stranger in Blender if the code-native prototypes establish the right visual language.
6. Add secondary props and a credits/disclaimer screen last.

The first visual milestone should be three genuinely three-dimensional bodies in the live graph, not a large collection of flat pictures. That will test the rendering language and GPU cost before the full set is produced.
