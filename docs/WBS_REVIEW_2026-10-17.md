## 已复现问题（等用户决定）

| 优先级 | 问题与触发 | 影响 | 建议 |
| --- | --- | --- | --- |
| 高 | `wbs-core.js cpm()` 用 terminal 判断外部前置是否满足；A 已取消，B blockedBy A，单独计算 B，得到 valid=true、es=0 | 取消/重复不代表交付满足，但后续方向被当成可立即开始 | 区分完成与取消；取消前置提示待确认，由用户在 Linear 解除/替代依赖后再预测 |
| 高 | `wbs.js plan()` 指定一个无子 Issue 的父 TASK 时，只取 descendants 的叶子，结果为空；该父 TASK 即使 duration=2，结果也是 valid=true、total=0 | 错误地展示零天排期；缺工期时也可能显示为有效空计划 | 明确无子项父 TASK 是自身工作包还是未拆解；前者计自身，后者标记未具备排期条件 |
| 中 | `renderNetwork()` 按所有节点绘制依赖连线，随后仅对卡片应用人员/状态/关键词筛选 | 连线指向空白，看起来像数据丢失，隐藏前置的含义不明确 | 保留计算完整性；显示隐藏前置占位或只画可见端点间连线并提示过滤数量 |
| 中 | `renderLinks()` 直接使用 shownRoots，没有应用 prefs.scope；设置父 TASK 范围后切飞书对账，仍列出其他父 TASK | 同一筛选控件在不同视图中表现不一致，容易关联错任务 | 统一各视图的范围解析，并添加切换视图回归 |

复现方式：以 Node 加载真实 wbs-core.js；对 wbs.js 的 plan/renderNetwork/renderLinks 提取原函数，在隔离上下文传入虚构任务。四个结果已实际验证。没有修改生产任务验证这些问题。

## 其他风险与优化建议

1. 关联草稿覆盖风险：刷新 Linear 保存后无条件 openIssue(selectedIssue)，会重建 linkForm；用户未保存的记录选择和说明可能丢失。建议草稿 dirty 标识、切换/刷新确认以及版本比较。此项经源码确认调用链，未通过真实刷新重现，避免写入本机快照。
2. 同步速度：交接记录为 294 Issue / 33 次 GraphQL / 约 30 秒。本轮未重复发起全量 Linear 刷新。建议先加阶段/页数进度、单次刷新防重，再考虑增量 + 周期全量对账；需覆盖删除、归档、迁移，不能只合并 updatedAt。
3. 默认概览信息量：当前负责人图例、重复截止/关联信息，以及每个空模块都占空间。建议图例收纳、空模块可折叠；关系图全图保持概览，放大后显示详情，不单纯缩小整张卡片文字。
4. 任务要求目前以 pre 展示 Markdown 原文。可复用已修好的安全 Markdown 阅读器，提高长合同的层次，同时保留原文切换。
5. WBS 完成度只应表示子项进度，不能自动代表父合同验收通过。CPM、人员负载与绩效评分应维持独立，避免用 Done 数或 estimate 代替工期/验收。
