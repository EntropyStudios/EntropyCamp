# 部门任务功能交接

更新日期：2026-10-17。交接对象：EntropyCamp前端及后端维护工程师。

本文件整理本轮对话中增加、调整的部门任务功能。以当前源码为准，不把讨论过的计划写成已实现；不涵盖其他工程师开发的钟面、小组件、提醒图谱等功能。

## 1. 项目与运行

- 仓库：`/mnt/mydisk/My_project/Entropy/EntropyCamp`。
- 服务：`http://127.0.0.1:8765`，用户级 `entropycamp.service`。
- 技术：Python标准库服务、原生HTML/CSS/JS，无前端构建步骤。
- 静态资源返回 `Cache-Control: no-store`，改JS/CSS后刷新页面即可；后端修改需要重启服务。
- 工作区包含多人的未提交修改和未跟踪文件。不要按“未跟踪＝临时文件”删除，不要覆盖其他人的工作；本次交接未提交代码。
- 本机私有数据在 `~/.local/share/entropycamp/`，不在静态站点内。不要把令牌、数据库或原始对话打包进Git。

## 2. 已实现的功能

### 2.1 任务同步：人工审核、AI执行

入口：`/task-sync.html`。

流程：选择来源对话 → 冻结增量时间窗口和原文 → 复制分析请求给统管AI → AI通过接口回写建议 → 用户逐项勾选、编辑及回答问题 → 保存人工确认快照 → 复制执行请求 → AI执行后回写结果。

程序不自动启动Codex回合，也不自动创建Linear任务或发布评论。这样避免把统管对话ID失效、跨主机线程找不到等问题混进执行流程。

已支持：

- 来源对话多选，保存上次选择，按最近更新时间排序；来源携带主机信息。
- 保存每批原始材料、分析、人工确认版本、执行历史，旧失败批次可复用材料重新分析。
- 建议逐项勾选及编辑，不要求只能选一个；确认时冻结快照，不以之后未确认的修改代替执行授权。
- AI通过API写入分析、进度和最终结果；页面显示批次状态和执行结果。
- 可选问答区，0～20题；支持选项、自由回答、忽略。问题关联建议稳定ID，未确认的关联项默认不选，并在提交时检查。
- 回写使用expectedRevision检测并发冲突，冲突不能静默覆盖。
- 执行回执支持operations：逐项保存success/failed/skipped/unknown、实际Issue编号、评论ID及链接，供下轮核对去重。

建议分类：

| 字段 | 含义 |
|---|---|
| linearUpdates | 已有子Issue过程更新；合同变更用scope_change另列 |
| newLinearTasks | 已确认父TASK下的新子Issue建议 |
| parentTaskRequests | 父任务讨论草稿，只复制到统管对话，不参与执行 |
| acceptanceRequests | 父TASK申请验收建议，须人工确认 |
| feishuTasks | 用户可复制的飞书草稿，不自动写入 |
| questions | 归属、证据、需求、参数待确认项 |
| ignored | 未形成任务建议的内容及原因 |

### 2.2 WBS部门任务页面

入口：`/wbs.html`，主页已增加入口。

- 层级为Project → Module → 父TASK → 推进子Issue，按Linear真实parent关系组织，不按标题或REQ标签推断层级。
- 卡片总览与网状关系图两种视图。网状图以项目为中心，模块、父TASK向四周展开，子Issue默认收起。
- 支持节点拖动、背景平移、缩放、查看全图、回到中心、重新排布及收起子Issue。
- 卡片显示状态、负责人、截止日期、子Issue总数/完成数及飞书关联数量。
- 状态色和负责人标识分开；无负责人显示“待接取”。Todo有负责人表示已接取待开始，无负责人表示待接取。
- 支持项目、父TASK范围、负责人、状态、关键词、隐藏已结束任务筛选。
- 展开父TASK可查看子项，包括已完成子项；仍受指定人员、状态和关键词筛选影响。
- 详情展示要求、真实父级、子项和飞书关联。原生Linear链接可直接跳转。
- 项目、视图、筛选、展开状态、节点位置及缩放保存在浏览器localStorage，不存入共享任务快照；URL可指定project/view/issue。
- 顶部保留返回主页、飞书任务入口；连接和同步设置折叠收纳。

Module来自标签组 `WBS · 项目完整名称` 的子标签。项目改名需要核对模块识别，不能只改显示名。

### 2.3 Linear登录与只读同步

- 使用OAuth Authorization Code + PKCE，仅申请read权限。
- 首次配置Client ID，之后登录一次；后端保存令牌并在过期前续期。不需要搬运同事的密钥，不需要前端保存Client Secret。
- 回调固定为 `http://127.0.0.1:8765/api/wbs/oauth/callback`。
- state与HttpOnly/SameSite Cookie绑定，10分钟过期；回调日志屏蔽code。
- 私有令牌文件 `linear-oauth.json` 权限0600；状态接口不返回令牌。
- 退出清除本机令牌，保留任务快照。旧只读API密钥方式保留兼容。
- 读取MOTION团队项目、模块标签及全部Issue，包含完整描述、负责人、状态、父级、Project、里程碑、真实阻塞关系；嵌套关系也处理分页。
- 完整读取成功才允许导入，失败保留旧快照；revision防止并发覆盖，保留已确认飞书关联。

**最新修复：**“刷新Linear任务”原来只生成预览，需要再点应用，导致用户以为刷新完成但卡片仍是旧状态。现按钮依次调用refresh和import，保存成功才更新页面并提示完成；失败明确提示仍在显示旧数据。底层refresh API仍不保存，不能把接口返回成功当成已落盘。

页面打开、浏览器刷新或“重新载入本机数据”只读取本地快照，**目前没有自动从Linear同步或实时推送**。

### 2.4 CPM与甘特图

- 使用Linear真实blockedBy关系，Related和父子关系不自动转成依赖。
- 父TASK总览可投影子方向的跨TASK依赖；内部视图使用叶子任务，避免父子工期重复累计。
- 工期只读取描述中明确的 `WBS 剩余工期：N 个工作日` 或 `WBS 预计工期：N 个工作日`。
- 不把绩效分、estimate、截止日期差当作工期。
- 检查缺工期、外部未完成前置、依赖不一致和循环。条件不足时可看依赖图，但不提供不可靠的关键路径或甘特预测。
- 完整数据下按相对工作日计算，不包含人员资源调度和完整节假日日历。

### 2.5 飞书任务关联与跳转

- 复用既有performance API查询运控、力控任务，按has_more分页、按记录ID去重。
- 父TASK详情中手选飞书记录，并填写目的、范围、验收对应依据；支持一对多。
- 子Issue通过真实父TASK查看关联，不单独创建公司任务映射。
- WBS跳转 `performance.html?record=...`；飞书详情可反向跳转对应Linear/WBS。
- 关联关系本地保存，刷新Linear时保留；不按相似标题自动绑定，不互相覆盖状态。
- 未读取完整、查询失败或缓存等情况显示提示。接口未提供飞书网页原地址，当前跳转的是本机记录详情。

## 3. 必须保留的业务规则

1. 父TASK由李昊洋与统管AI确认后发布，小前端不通过同步流程发布父任务。
2. 日常推进记录写子Issue。父Issue评论只用于申请验收和评价；已确认的合同调整写父描述，执行审计留在同步回执。
3. 子Issue是一个工作方向，可以承载多次操作和实验，不是一操作一单。
4. 归属必须核对目的、范围、验收和来源证据。标题相似、同项目、Related不证明归属。
5. 缺合适父任务时先提议，确认发布后再二次分析、创建子Issue，不能先建无父任务。
6. 测试通过、PR合并、所有子Issue Done都不自动代表父TASK验收通过；不自动评分、改父Done。
7. 飞书只读对账和草稿，未经单独授权不写入。Linear状态不自动覆盖飞书，反之亦然。
8. 历史对话是材料，不是本轮操作授权；人工回答若实质改变已确认建议，需要再次澄清范围。
9. 未指定负责人不默认继承父负责人；但已明确负责人时，原生字段和描述应一致，不再保留“接取后确定”。

注意：目前大部分规则通过提示词及字段校验实现，**不是程序已经核验了Linear合同语义**。AI执行前仍要重读外部实际数据。

## 5. 关键接口与数据

所有POST要求 `Content-Type: application/json`、`X-Lumen-Request: 1`，遵守本机Host/Origin检查。

| 接口 | 用途 |
|---|---|
| GET /api/task-sync | 批次、来源和配置 |
| GET /api/task-sync/run?id=... | 原始材料、Schema、分析、问题、确认及执行历史 |
| POST /api/task-sync/analyze | 冻结增量材料，不自动调用AI |
| POST /api/task-sync/submit | 保存人工确认快照 |
| GET /api/task-sync/request?id=...&phase=... | 生成分析/执行请求 |
| POST /api/task-sync/result | 回写analysis/progress/execution及operations |
| GET /api/wbs | 已保存任务镜像及revision |
| POST /api/wbs/refresh | 读取完整Linear候选及差异，不保存 |
| POST /api/wbs/import | 用complete与expectedRevision保存镜像 |
| POST /api/wbs/preview | AI导入前核对差异 |
| POST /api/wbs/link | 保存父TASK与飞书记录的确认关联 |
| GET /api/wbs/oauth/status | 脱敏登录状态 |
| POST /api/wbs/oauth/configure、start、logout | OAuth配置、登录、退出 |

业务主状态在state.sqlite3；批次材料/确认文件在task-sync目录；WBS镜像和映射在wbs.json。不能把它们合并覆盖，也不能把浏览器偏好作为共享业务主数据。

## 6. 已知问题与优化优先级

### 优先：同步速度和反馈

10/16实测：294个Issue，全量读取33次GraphQL请求，共29.73秒；本地快照读取约0.006秒。Issue每页10个且串行，当前页面选单项目也会读取全部门。这是已定位的主要等待来源，**尚未做增量提速**。

建议：保留现有数据供浏览，增加阶段/页数进度；增量更新搭配周期全量对账。必须处理删除、归档、跨项目迁移和父子关系变化，不能只拉updatedAt后无限合并。也不要只放大嵌套查询页数，之前已遇到查询复杂度限制。

### 优先：刷新链路回归

按钮已经修成读取后保存，但尚无持久化的浏览器端到端刷新回归测试；本轮只用Node沙盒对真实按钮处理函数验证了“保存成功显示新值”和“保存失败保留旧值”两条路径。

建议锁定：Todo无负责人→Done有负责人、保存冲突、读取失败、快速重复点击、多标签页、页面切回、飞书关联不丢、当前项目不跳转。前端还残留旧预览dialog及应用处理逻辑，可在核对调用方后整理。

### 优先：提示词与规则统一

刚发生过父Issue误发“合同确认”评论，已删除；也发生过补建子Issue未指定实际负责人。规则应同时覆盖提示词、预览和执行回执，不能只依靠AI记住。验收结果需要易读，避免把内部建议reason整段直接复制成评论。

### 后续：执行结果的准确表达

批次completed表示回执已保存，不表示所有操作都成功；unknown也不允许自动重试。应突出部分成功、跳过与状态不明，提供实际Issue/评论跳转。不要把“已创建、待补录”的旧message当成最终完成情况。

### 后续：绩效台账尚未实现

已讨论“逐次验收记分、月底汇总”，但没有开发台账或自动计分。公式为基础分×微调系数×交付评价；结果性50%、规范性25%、工程性25%。组内配比未统一定死，评分由李昊洋确认；不应据此自动写评分或关闭任务。
